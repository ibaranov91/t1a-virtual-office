# The Deck: product brief

This started as the brief for the first prototype, written at kickoff on Oct 15, 2026. It was updated on Oct 16 to
match what was built. "Changed from the first brief" notes record where the build went past it on purpose.

## What it is
A persistent virtual office for a ~30-person, fully remote consultancy. One cozy pixel-art floor where every
teammate is a little character in a room. The point is ambient awareness (who's around, what they're on) and a
zero-friction "tap on the shoulder". It should feel like a warm Stardew Valley interior, but it is a tool first: the
games, hats and pets are there to make people want to open it in the morning.

## Core concepts
- **Floor**: one 2D top-down tilemap of 16 px tiles, generated by `scripts/gen-map.mjs` into `shared/tilemap.json`
  (floor, walls, furniture, walkable mask, rooms). Today it is 85×73 tiles with 18 rooms (`docs/MAP.md`).
  Each room has a name, rules and spots where characters settle.
- **Room rules are data, not code**: knock policy (`allow`, `later`, `disabled`), open voice, admin-only access and
  labels live on the room in the tilemap. Focus and Studio are quiet (no knocks). Meeting and Library send knocks to
  Later. Coffee, Music, the Arcade and the Book Club are open voice rooms.
- **Character**: a 16×24 pixel sprite with 4 directions, walk and idle frames. Body, hair, skin, clothes and accessories
  are chosen by each person. Below it a nameplate, above it bubbles: away, in a call, in a meeting, talking, knock,
  status text.
- **Walking**: click a walkable tile and your character paths there with A* on the walkable mask. The server sends
  one `move`. Every client computes the same path from the same map and animates it from `startedAt`, so everyone
  sees the same walk without per-frame streaming.
- **Room membership** comes from the tile you stand on, not from the click.
- **Presence**: online, away, in a call, offline, plus a status text. Away is set by hand.
- **Knock**: click someone and knock. Your character walks over, a "!" pops over their head, and they get Accept or
  Later. Accept puts you both in a call with built-in voice; Google Meet is one click away for video or screen
  sharing. Changed from the first brief: it had no built-in audio, only a meeting link.
- **Calendar**: with Google connected, meetings from your calendar show up on the floor. Guests get a heads-up and
  one click into a private copy of the Meeting room.

## Architecture
- **Server**: Node + TypeScript, one process. WebSocket (`ws`) for realtime, a small REST API for login, OAuth,
  uploads and the Mac app. State in memory, saved to `data/state.json` every 30 s, with daily backups.
  Sign-in: NetBird SSO on prod, a name behind a NetBird PIN on test instances, a shared token in dev.
- **Protocol**: the server is the source of truth. Clients send intents, the server validates them and broadcasts
  events. Every message type is in `shared/protocol.ts`.
- **Web client**: React + TypeScript + Vite. The floor is one `<canvas>` with one `requestAnimationFrame` loop:
  tiles, then characters sorted by y, then bubbles and nameplates, at whole-pixel zoom levels. React only draws the
  chrome around it (sidebar, panels, toasts). It works from 360 px wide, with a thumb dock on phones.
- **Assets**: all art is generated by `scripts/gen-assets.mjs` into `client/public/assets/` and loaded through a
  sprite atlas (`atlas.json`), so swapping the art doesn't touch code. Changed from the first brief: it planned a CC0
  tile pack.
- **macOS**: a Swift menu bar app (AppKit + WKWebView) that hosts the web client: popover, window, pinned to the
  desktop, native knock cards, unread count, self-update. Changed from the first brief: it planned a Tauri wrapper.
- **Dev data**: bots that wander, change status and knock on each other, so the floor looks alive when testing
  alone (`npm run dev` starts 4).

## Design
Cute, warm, cozy pixel art in the Stardew Valley interior style.
- Palette: warm wood floors, rugs per room, muted but saturated colours, soft dark outlines. Dark UI chrome around
  the canvas so the floor stays the focus. Type sizes and UI rules: `docs/UI.md`.
- Room character: Coffee has a steaming machine, Focus has desks and lamps, Meeting has a long table and a wall
  screen, the Lobby has plants, a notice board, the reception bell and a hat rack, Co-working has world clocks.
- A subtle day/night tint based on the viewer's local time.
- Motion: smooth walking, a small idle bob, bubbles that pop in with a two-frame bounce.
- The map comes first: things you do live on objects in the room (a jukebox, a calendar on the wall, a cabinet).
  The sidebar lists rooms and people for quick navigation, the way Discord lists channels.

## Not now (design for it, don't build it)
Slack/Teams status sync, automatic away detection, sign-in without NetBird (email code or magic link), a database
instead of the JSON file, editing walls and rooms (edit mode moves furniture only), video inside The Deck (Meet does
that). Keep the tilemap, rooms, spots and presence as data so these can be added without a rewrite.
