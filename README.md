# The Deck — prototype

Virtual office for T1A. See `REQUIREMENTS.md`.

```bash
npm install
npm run dev        # server :8787 + Vite client :5173
```

`npm run dev:mesh` serves the same thing over HTTPS (self-signed) on localhost and on this machine's
NordVPN Meshnet address (100.64.0.0/10, auto-detected; override with `DECK_MESH_IP`). Other Meshnet devices open
`https://<mesh-ip>:5173`. HTTPS is what gives them microphone access for voice. Requests from other networks are dropped,
and the API always listens on 127.0.0.1 in dev.

Open http://localhost:5173, enter any name, token `deck` (override with `DECK_TOKEN`).
`BOTS=0` disables the 12 dev bots. State is dumped to `data/state.json` every 30 s.

## Layout
- `shared/tilemap.json`: floor, walls, walkable mask, rooms (type, capacity, spots, knock rules, meeting link), furniture. Generated by `scripts/gen-map.mjs`.
- `shared/map.ts`: deterministic A* + path sampling, used by server and clients so everyone sees the same walk.
- `shared/protocol.ts`: WS events (`hello`, `state`, `move`, `status`, `presence`, `emote`, `knock`, `knock_reply`).
- `server/`: Node + `ws`, in-memory world, knock flow, bots.
- `client/`: React chrome + a single-canvas engine (`engine.ts`).
- `client/public/assets/`: `atlas.json` + `world.png` + `characters.png` + `accessories.png`. These are a procedural CC0 placeholder pack made by `scripts/gen-assets.mjs`. Replace the files to swap the art; the code reads sprite metadata from `atlas.json`.

`npm run gen` regenerates the map and the art.

## Deploy
Several copies ("instances") run side by side on the vOffice box, each fully separate: own port,
folder, data, settings and systemd service. They're listed in `scripts/instances.txt`:

| instance | port | owner | URL |
|---|---|---|---|
| `prod` (login: sso) | 8080 | ibaranov91 | https://voffice.t1a.io |
| `andr` (login: pin) | 8081 | booandrew | https://voffice-andr.pub.t1a.cloud |
| `var` (login: pin) | 8082 | varvaratikhonova-ui | https://voffice-var.pub.t1a.cloud |
| `iva` (login: pin) | 8083 | ibaranov91 | https://voffice-iva.pub.t1a.cloud |

```bash
scripts/deploy.sh andr      # your instance; no argument deploys prod
```

It builds the client locally, rsyncs your working copy to the box, runs `npm ci` and restarts
`deck-<name>` (prod: `the-deck`). Two deploys of the same instance wait for each other, and a port
already used by another instance is refused.

- **Access:** you need SSH to the box as `Hetzner2-vOffice` in `~/.ssh/config` (or set `DECK_SSH_HOST`).
- **New instance:** add a line to `scripts/instances.txt` with a free port, add a NetBird reverse-proxy
  entry to `http://10.200.142.211:<port>`, then deploy.
- **Settings:** `/etc/deck-<name>.env` (prod: `/etc/the-deck.env`), created on the first deploy:
  `DECK_PORT`, `DECK_HOST`, `BOTS`, `BOT_COUNT`, `NETBIRD_AUTH`, `NETBIRD_TRUSTED_CIDR`, `NETBIRD_TRUSTED_PEER`,
  `DECK_TOKEN`, `OPEN_LOGIN`.
- **Login:** set per instance in `scripts/instances.txt` and re-applied on every deploy.
  `sso`: NetBird sign-in ("Continue as …"); the proxy entry must use NetBird SSO so it passes `X-NetBird-User`.
  `pin`: for public proxy entries protected by a NetBird PIN. Pick any name, no password; the PIN is the only gate.
- **Logs:** `ssh Hetzner2-vOffice journalctl -u deck-<name> -f`.

### Lofi Girl TV

The Music room TV discovers the active **lofi hip hop radio · relax/study** broadcast from the public
Lofi Girl channel page (`server/src/lofi.ts`); no YouTube API key is required. Lookups are shared and
cached for five minutes. Open players check our `/api/lofi` endpoint every 30 seconds and replace a
finished broadcast when a new one appears. No active radio yields Offline; a failed lookup yields
Unavailable and retries after a minute. A previously found stream can remain playable for up to
30 minutes during a lookup outage, with no LIVE badge. The resolver depends on YouTube's page format.

A **Listening to Lofi Girl** tag appears above a character only during audible playback, including
changes made with YouTube's own mute/volume controls. This status is shared across clients, tracked
per browser connection, and cleared on room exit or disconnect; it is never saved to disk.
