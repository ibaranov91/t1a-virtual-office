# The Deck — prototype

Virtual office for T1A. See `REQUIREMENTS.md`.

```bash
npm install
npm run dev        # server :8787 + Vite client :5173
```

Open http://localhost:5173, enter any name, token `deck` (override with `DECK_TOKEN`).
`BOTS=0` disables the 12 dev bots. State is dumped to `data/state.json` every 30 s.

## Layout
- `shared/tilemap.json`: floor, walls, walkable mask, rooms (type, capacity, spots, knock rules, meeting link), furniture. Generated by `scripts/gen-map.mjs`.
- `shared/map.ts`: deterministic A* + path sampling, used by server and clients so everyone sees the same walk.
- `shared/protocol.ts`: WS events (`hello`, `state`, `move`, `status`, `presence`, `emote`, `knock`, `knock_reply`).
- `server/`: Node + `ws`, in-memory world, knock flow, bots.
- `client/`: React chrome + a single-canvas engine (`engine.ts`).
- `client/public/assets/`: `atlas.json` + `world.png` + `characters.png`. These are a procedural CC0 placeholder pack made by `scripts/gen-assets.mjs`. Replace the three files to swap the art; the code only uses frame names.

`npm run gen` regenerates the map and the art.

## Deploy
`scripts/deploy.sh` builds the client, rsyncs to `Hetzner2-vOffice:/opt/the-deck`, runs `npm ci`, and restarts the `the-deck` systemd service. The server listens on `10.200.142.211:8080` behind the reverse proxy at https://voffice.t1a.io and serves `client/dist` itself.
Config is in `/etc/the-deck.env` (`DECK_TOKEN`, `DECK_PORT`, `DECK_HOST`, `BOTS`). The team token is generated on the first deploy; read it with `ssh Hetzner2-vOffice sudo cat /etc/the-deck.env`.
Logs: `ssh Hetzner2-vOffice journalctl -u the-deck -f`.
