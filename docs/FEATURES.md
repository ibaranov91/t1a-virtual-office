# Features and where they live

Every user-facing feature, the code behind it, the tests that cover it and its design spec. Paths are relative to
the repo root. Specs are in [`docs/superpowers/specs/`](superpowers/specs/); the Spec column gives the file name.
Tests run with `npm test` (`server/src/*.test.ts`, `client/src/*.test.ts`, `shared/table/*.test.ts`).

A few files are touched by almost every feature and are named only where a feature has its own code in them:
`server/src/world.ts` (all state, the `handle()` switch, one `// ---------- <feature>` block per feature),
`client/src/net.ts` (store + WebSocket), `client/src/engine.ts` (the canvas floor), `client/src/App.tsx` (React
chrome), `shared/protocol.ts`, `shared/map.ts` (`USE_KINDS`, A*, rooms, layout) and `shared/tilemap.json` (generated
by `scripts/gen-map.mjs`). All art comes from `scripts/gen-assets.mjs`.

To find everything about one object, room or tile: `npm run where -- <thing>`. To add a feature:
[ADDING-A-FEATURE.md](ADDING-A-FEATURE.md).

## Protocol messages per feature

Client → server messages are `ClientMsg`, server → client messages are `ServerMsg`, both in `shared/protocol.ts`.
`notice` (server → client) is the generic refusal text most features use.

C→S is a `ClientMsg`, S→C is a `ServerMsg`. `notice` (S→C) is the generic refusal text used by most features.
